# 桌面登录流程

Portal、SIS、Moodle 各保留一个固定服务记录，共享原有 `persist:myhku-hku` 分区。SSO 依次进行；跳转到 Microsoft、ADFS 或 CAS 后仍属于原服务。启动、重复点击登录、刷新均复用记录。Windows 关闭仪表盘会退出后台会话及 bridge，再次启动只允许一个应用实例。

每秒检查页面，加载结束后先等待 1.8 秒。自动点击 SIS 的 Portal Login、Moodle 的 HKU Portal User；保存的凭据仅交给身份服务，绝不填写 SIS/Moodle 访客表单。双字段身份表单同时填写用户名和密码；同文档同一步只提交一次，同一流程每一步最多自动尝试两次。正在回调或尚未渲染输入框的页面继续等待，不直接提示 2FA。

成功必须有官方页面的登录后 DOM 标记（例如退出入口、Moodle 用户/课程区域或 SIS 课表控件），且连续两次观察稳定；单独的业务网址、空白页和中间跳转不能证明成功。Portal 成功也不能单独证明 SIS 成功。身份验证挑战立即显示官方窗口，其他需要手动操作的页面给予 20 秒恢复时间，未完成流程在 90 秒后显示实际页面供检查。用户主动打开课程或服务页面时保留窗口。

登录状态由主进程维护，仪表盘通过事件更新，并每 5 秒获取当前状态以恢复遗漏事件。登录成功无需等到课程爬取结束；规范化数据提交完成后再通知界面读取数据。刷新不会重载仍在认证中的窗口。已连接的服务不会因再次点登录而新开会话。

运行 `npm run test:desktop-auth`：包含队列单元测试、真实 Chromium DOM 测试和生产主进程/preload 集成测试。集成测试使用独立临时配置、随机本机端口及本地官方页面替身；仅使用保留示例域名的虚构账户，不读取已安装版账户或连接真实 HKU 登录服务。

本地替身测试覆盖慢 CAS 回调、已有 SSO、访客入口、重复请求、状态恢复与刷新。真实 HKU 的 MFA、学校页面结构及实际账户权限仍需在更新后的客户端验证。
