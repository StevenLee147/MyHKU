# MyHKU 首版需求规格

日期：2026-09-09。状态：已根据需求访谈整理；下文明确区分用户已确认的需求与实施默认值。

## 1. 产品目标与已确认范围

为个人提供 Windows、macOS、Android 客户端，在统一的应用仪表盘中查看 HKU 学习信息，减少重复进入学校网站和重复登录。

“原生仪表盘”表示独立客户端体验与结构化数据展示，具体 UI 框架尚未锁定。

| 模块 | 已确认的首版功能 |
| --- | --- |
| 平台 | Windows、macOS、Android |
| 登录 | 首次在官方登录页手动完成 SSO/MFA，之后复用有效会话；失效后回到官方登录页手动认证 |
| Portal / SIS | 作为登录与课表数据入口；SIS 只提取课表 |
| 课表 | 周视图，显示课程名称、时间、地点、教师 |
| Moodle | 课程列表、公告、作业截止日期、课程资料下载、待办状态、成绩 |
| 操作范围 | 只读查看和用户主动下载资料 |
| 通知 | 应用打开时刷新、用户手动刷新；应用持续打开时默认每天刷新一次，并对 Moodle 新作业、临近截止事项和课表变化发送桌面/手机通知 |
| 数据保存 | 仅本地保存；使用平台系统安全存储保护应用持有的会话秘密和加密密钥 |
| 邮箱 | 后续版本 |

已确认的平台安全存储方向：Windows Credential Manager、macOS Keychain、Android Keystore。它们保存密钥或小型秘密；应用缓存通过这些密钥加密，不将整个数据集直接塞入钥匙串。

## 2. 功能行为

### 登录与会话

- 提供官方登录流程入口，用户本人输入账号密码并完成学校要求的认证。
- 应用重新打开时检查已有会话；会话仍有效则恢复同步。
- Portal、SIS、Moodle 分别呈现连接状态，不能因一个服务登录成功就假定全部成功。
- 在一次前台或受支持的日更检查中发现会话失效时暂停该服务同步，发出一次重新登录提醒；用户打开应用后进入官方认证页面。
- 恢复登录后继续同步；离线或未重新登录期间仍可查看带有更新时间的本地缓存。
- “自动登录”的验收目标是复用有效会话；学校要求重新认证时仍须完成认证，不能承诺永久登录。

### 课表

- 从已登录的 SIS 获取当前学期课表并转为统一数据模型。
- 按周查看与切换日期，展示课程名称、开始/结束时间、地点、教师。
- 如学校未提供教师或地点，明确显示“未提供”，不推断或编造。
- 正确处理来源中已有的日期范围、周次和例外日期，避免将非每周课程错误重复展示；这属于课表准确性要求。
- 显示最近成功同步时间。解析失败保留上次有效数据，不把失败当作课表清空。

### Moodle

- 按课程查看公告、作业及截止时间、资料列表、待办状态、成绩。
- 待办状态和成绩以当前账号可见的 Moodle 数据为准；“未发布”“未获取”“不适用”与数值 0 分区别显示。
- 资料由用户点击后下载，展示进度、成功或失败状态，并允许打开文件或所在位置。
- 自动同步不得改变提交状态、已读状态或完成标记。对会触发此类变化的页面访问，需先寻找只读数据来源。
- 原网页仅用于认证或用户明确选择的辅助查看入口；仪表盘是主要使用方式。

### 本地通知

- 提醒新作业、作业临近截止，以及已成功同步确认的课表新增/取消/时间或地点变化。
- 首次完整同步建立基线，不把全部已有作业当作新作业发送通知。
- 对相同事件去重；课程成绩默认不在通知中展示。
- 点击通知进入对应课程、作业或课表。
- 通知权限未授予、同步失败或后台受限时，在应用内展示实际状态。
- 每台设备独立管理提醒；仅本地保存意味着多台设备可能分别提醒同一事件。

## 3. 可调整的实施默认值

以下属于方案默认值，并非用户逐项明确选择，可在后续实施时调整。

| 项目 | 默认行为 |
| --- | --- |
| 账号 | 每台设备一个 HKU 账号，设备之间独立登录 |
| 首页 | 今日课程、近期作业、最新公告、同步状态 |
| 界面 | 简体中文，保留学校课程/资料原文；跟随系统深浅色 |
| 时区 | 课程与作业使用香港时间 Asia/Hong_Kong，并标注时区 |
| 同步 | 每次打开应用时刷新；提供手动刷新按钮；应用持续打开时默认每天刷新一次 |
| 截止提醒 | 默认提前 24 小时和 1 小时；过滤已确认完成的事项；临时首次发现的截止事项只给合并提醒 |
| 桌面运行 | 关闭主窗口即停止同步；不要求托盘常驻或开机自动启动 |
| Android 后台 | 首版不要求应用关闭后持续同步；打开应用时刷新，持续打开时按日刷新 |
| 缓存 | 本地加密保存最近成功同步的数据；离线可查看，展示数据新鲜度 |
| 附件 | 仅主动下载；导出到用户选择的目录后按普通文件管理，不能宣称仍由应用加密保护 |
| 通知隐私 | 默认隐藏成绩、学号等敏感内容 |
| 清理 | 提供退出账号并清除应用会话与缓存的入口；已导出的资料由用户管理 |
| 云服务 | 无自建同步服务器、无账号跨设备同步、无默认遥测 |

## 4. 首版不包含

- HKU 邮箱、发信/回复。
- 选课/退课、作业提交、讨论回复或手动修改 Moodle 完成状态。
- SIS 个人信息、财务/缴费、考试模块、成绩模块；成绩仅来自 Moodle。
- 月视图、日历导出/Google Calendar 同步、独立的考试安排模块。
- 多账号管理、自建云端数据同步。

## 5. 验收标准

1. Windows、macOS、Android 都可安装、启动并完成官方登录流程；单个平台演示通过不能代替其他平台验证。
2. 完全退出再启动后，有效学校会话能复用；过期会话可正确提示并恢复认证。
3. 选定一周的课表与 SIS 原始数据一致，四个要求字段准确；空数据和解析失败有不同状态。
4. Moodle 列表、截止时间、待办和可见成绩与原站一致，资料可下载并正确打开。
5. 首次同步无通知轰炸；新增作业和课表变化去重提醒；重复刷新不会重复发送相同通知。
6. 无网络或会话失效时保留缓存及更新时间；不会将过时数据标成刚同步成功。
7. 应用管理的数据库和会话秘密不以明文写入普通配置或日志；系统 WebView 持久化存储需逐平台验证，不能仅凭使用钥匙串就判定整个浏览器 Profile 已加密。
8. 账号退出后清除该账号应用缓存、会话秘密、浏览器会话和待触发提醒；切换账号不会看到之前账号的数据。
9. 桌面与 Android 的前台日更计时、通知权限和点击跳转分别验证；系统休眠或应用关闭期间不承诺实时更新。

## 6. 实施前需用实际环境验证

- HKU 当前登录链、跨域跳转、MFA 和内嵌浏览器兼容性。
- 应用重启后的会话保留是否符合学校 Cookie/Token 的实际有效期策略。
- SIS 课表以及 Moodle 各项数据是否存在当前账号可用的只读接口、导出或可稳定解析的页面。
- 应用持续打开时的日更刷新、系统休眠/网络切换后的恢复行为，以及三端通知权限。
- 三个平台的 Cookie/浏览器存储保护、安装包和通知实机表现。

验证时由用户在官方页面登录，不要求在对话中提供账号密码、Cookie 或访问令牌。
